## 1. 审查范围与证据规则

范围包括 Web 原型 `index.html`、Flutter `lib/`、Node/Express `server/`、知识库、自动化测试和 `docs/`。问题只有在满足下列至少一项后才写入：代码路径可直接证明、静态检查可重复报错、浏览器/API 流程可重复失败。未运行成功的检查标为“未验证”，不冒充失败或通过。

- Web 核心首次训练链路已通过 2 条 Playwright 用例。
- 知识库 JSON 与索引此前已校验通过；内容仍需持续人工抽检。
- Node 源码 JavaScript 语法通过，但缺少接口自动化测试，不能判定生产可靠。
- Flutter 首轮 `flutter analyze/test` 因两个 Flutter 进程争用且长时间无输出而中止；随后静态审查确认网络层存在编译级契约问题并已修复，仍需重新执行完整 Flutter 检查。
- 文档此前把原型功能误写为生产完成，已在 v2.4 开发计划中校准。
