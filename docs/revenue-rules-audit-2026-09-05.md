# 营收、奖励与解锁规则审查报告

**审查日期：2026-09-05｜最终复核：2026-09-08｜范围：Web 原型、Flutter 会员模型、Node 演示 API、PRD 与拆分文档**

## 1. 结论

原 DeepSeek 方案可以作为产品方向，但不能直接上线：会员价格和次数在不同文件中互相矛盾，支付接口存在“调用即开通”的危险设计，免费训练次数没有跨天重置，积分上限把可消费余额误当成累计进度，场景有旧的自动解锁分支。上述问题已修复或改为安全阻断；当前版本可以做产品演示，不能产生真实收入。

## 2. 已确认并修复

| 签到奖励非原子 | 旧流程先增加积分/券，再写签到记录；并发或数据库故障可能出现重复奖励、孤立奖励或“签到失败但已发奖” | `CheckIn.settleAtomic()` 将用户锁、连续天数、券上限、积分入账和签到记录放在同一事务；唯一键冲突整体回滚并按重复签到返回 |

| 体验日卡自定义额度错误 | 代码曾允许体验日卡创建3个自定义场景，和价格/成本控制基线的1个不一致 | 已统一为免费/体验日卡1、周卡5、月卡10、年卡不限，并同步用户说明和 PRD |
| 自定义教练扣费缺少确认 | 创建入口曾直接扣除100积分，用户可能误触并无法在扣费前撤回 | 已增加扣费前确认，显示当前余额与扣费后余额；取消不会创建教练或改变积分 |
| 天赋接口前端重复扣费/成功码漂移 | 服务端事务已扣除积分，但前端成功回调仍可能再次扣减；服务端默认成功码为0而旧页面只识别200 | 服务端返回扣费后的可用/累计余额，前端只同步余额不重复扣费，并兼容0/200/`success:true`；缺少余额时 fail-safe 不本地扣减 |

## 3. 当前正式规则

### 3.1 收入

首期只开放会员订阅：免费版、体验日卡、周卡、月卡、年卡。单次场景、语音包和道具包仅为候选实验，当前不开放。真实支付必须经过：

`方案展示 → 服务端创建幂等订单 → 支付平台扣款 → 回调验签 → 权益账本入账 → 客户端查单 → 对账/退款`

服务端要重新计算价格，客户端金额不可信；订单、回调、退款、过期、拒付和道具发放必须可幂等、可追溯。模型调用（DeepSeek/TTS/ASR）、存储、客服、平台手续费和税费纳入毛利核算，并设置异常调用限频和未成年人消费限制。

当前原型不启用会员积分倍率、好感度倍率或周期道具发放；这些只能在服务端权益账本、成本测算和支付沙箱验收后作为新版本权益开放，不能写入当前营销承诺。

### 3.2 奖励与“惩罚”

- 免费用户每日5次；体验日卡每日20次；周卡/月卡/年卡不限免费额度，但仍受安全限频。
- 每日签到10积分+1张券，连续签到第7天额外3张券，券受持有上限约束。
- 有效训练需完成度≥70%且净得分≥30，基础约20–50积分；评分≥80额外10分，首次三星额外20分。
- 同一场景每天第4次起基础训练积分减半；双倍积分卡只在正常结算时使用。
- 道具按“库存扣减 + 会话限额”双重校验：时空穿梭券每次训练最多2张且同一轮最多1张（至少完成1轮后才能用）；提示卡每轮1张；情绪护盾每次训练1张且只抵消一轮负面评分的一半；双倍积分卡每次训练1张且不可叠加。道具不足、超限或训练未达标时不得伪造成功或重复扣发。
- 免费用户累计获得的等级进度积分封顶2000；消费可用积分不会降级。一般低分、能力不足或中途退出不扣历史积分、不降低好感度，只不给本次奖励并提供反馈；明确态度问题按下述好感度规则单独处理。
- 同一训练结算、作业、现实练习、复习和模板复制必须有状态/幂等保护；报告重绘不得再次发奖。
- Web 原型的作业完成和现实行动打卡仍按本地演示配置发放积分/好感度，并有重复/日期保护；服务端账本接入前不把它们计入生产收益或稳定奖励承诺。
- 好感度负向规则已开发为 Web 原型预览并在界面明确标注“未上线”：同一训练连续3次明确敷衍回答扣3点、明确不当/攻击性内容扣5点，各自每次训练最多一次，低分、能力不足、退出和穿梭券回退不扣已有好感度；连续3个未登录日后按每天1点衰减，单次登录补算最多7点。每次扣减均即时提示、记录原因并将数值限制在0–200；正式服务端审核与申诉账本上线前，不将其视为生产权益。
- 场景解锁积分折扣已开发为 Web 原型预览并在界面明确标注“未上线”：Lv.0–Lv.5分别为0%、10%、20%、30%、40%、50%，按折后整数成本（向上取整）扣可用积分；页面同时显示原价、折扣和节省值，穿梭券、累计等级积分和会员访问不受影响，资源只在确认后扣除。Node 生产端尚未接入好感度账本、原子扣费和永久解锁表，不能把 Web 本地折扣当成跨设备权益。

### 3.3 场景解锁

新账号首次从完整官方目录免费选1个，确认后不可更换。之后每个场景单独满足：最低等级（看累计进度积分）、可用积分余额、时空穿梭券余额。Web 原型会在确认时扣除本地演示资源并保存永久解锁；Node 训练启动已校验等级/积分/券门槛，但永久解锁记录、原子扣除和每日额度仍待生产权益账本接管。会员只在有效期内临时访问全部场景，不改变永久解锁记录。不采用72小时解锁冷却，以服务端频控、幂等和账本防刷。

## 4. 仍需生产实现

1. 微信/支付宝商户资质、支付参数、回调验签、订单表、支付流水、权益账本、退款/拒付和对账任务。
2. 服务端训练开始/结算接口，按账号原子扣减每日额度和道具，并防并发重复结算；同时迁移好感度正/负向事件和登录衰减流水。
3. 跨设备会员状态、积分/券余额、好感度和过期降级同步；客户端不得作为唯一数据源。
4. 实名、未成年人/防沉迷、税务/发票、隐私授权、客服申诉和数据删除流程。
5. 价格、转化、退款率、模型成本和毛利的埋点与监控；未接入支付前不统计虚假支付成功。
6. 过期券批次、会员专属模板和自定义场景额度需迁移到服务端账本，浏览器字段只能作为演示缓存。
7. 当前 Node 仍有部分历史 MySQL 模型与 SQLite 演示路由并存；场景永久解锁表/扣减接口、好感度账本和折扣重算尚未形成完整服务端闭环，不能把 Web 本地解锁状态或折后价格当成生产权益。
8. 当前 Web 会员页已移除未配置的原价、周期赠券、专属客服和 3D 等确定性承诺；未上线权益统一显示“待上线”，支付按钮仍只提示接入状态。
