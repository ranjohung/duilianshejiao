## 1. 文档概述与产品定位

### 1.1 产品定位

「对练社交」是一款 **AI驱动的对话社交训练App**，通过AI教练实时互动，结合CBT（认知行为疗法）、依恋理论、NVC（非暴力沟通）等心理学框架，为用户提供**结构化的社交技能训练**与**可量化的沟通能力提升**。

**定位于"社交技能训练平台"，不是"虚拟伴侣"或"情感陪伴"产品。**

### 1.2 一句话价值主张

> **"先在AI教练这里练一遍，再去面对真实世界。"**

### 1.3 核心差异化（vs 传统AI聊天）

| 维度 | 传统AI聊天 | 「对练社交」 |
|------|-----------|---------|
| **训练目标** | 无明确目标，泛泛而谈 | 每次对话有明确的社交能力训练目标 |
| **心理学框架** | 无 | CBT、依恋理论、NVC等心理学框架驱动 |
| **训练结构** | 自由聊天，无结构 | 场景化训练，有开始-过程-评估闭环 |
| **反馈机制** | 简单回复 | 多维度即时反馈+训练后评估报告 |
| **成长闭环** | 无成长追踪 | 能力雷达图+进步曲线+里程碑体系 |
| **形象联动** | 无 | 与"悦己颜值社"联动，社交自信与形象提升 |
| **合规设计** | 无实名认证/年龄分层/防沉迷/心理响应 | 实名认证 + 年龄分层 + 防沉迷 + 心理健康三级响应 |

### 1.4 技术目标

| 指标           | MVP目标                | 正式版目标        |
|----------------|------------------------|-------------------|
| AI推理响应时间 | < 3秒                  | < 2秒             |
| 教练渲染       | 2D动态立绘(Spine)      | 3D渲染 ≥ 30fps    |
| 语音延迟       | -                      | < 500ms           |
| DAU            | 1万                    | 10万              |
| 并发训练       | 500                    | 5000              |

## 2. 用户画像

### 2.1 核心用户

- **年龄段**：18-35岁都市年轻人
- **性别分布**：女性占比65-70%
- **地域**：一二线城市为主
- **消费能力**：中等以上，愿意为自我提升付费

### 2.2 四类典型用户

#### 用户A：社交焦虑人群（22-30岁）

- **特征**：在社交场合感到紧张不安，回避社交互动，担心被评价
- **核心需求**：在安全环境中练习社交，逐步建立信心
- **典型场景**：不敢参加聚会、害怕与陌生人交谈、在公共场合紧张
- **使用动机**：低成本试错，无真实社交压力

#### 用户B：职场新人（22-28岁）

- **特征**：初入职场，缺乏职场沟通经验，不知如何与上级/同事沟通
- **核心需求**：掌握职场沟通技巧，提升职业形象
- **典型场景**：面试紧张、汇报磕巴、不懂得体表达
- **使用动机**：职业发展刚需，希望快速提升

#### 用户C：沟通能力提升者（25-35岁）

- **特征**：有社交基础但希望精进，追求高阶沟通技巧
- **核心需求**：系统化提升沟通能力，学习特定技巧
- **典型场景**：想学谈判技巧、希望提升共情能力、改善亲密关系沟通
- **使用动机**：自我成长需求，愿意投入时间系统学习

#### 用户D：高难度场景需求者（22-40岁）

- **特征**：面临特定高难度社交场景，需要针对性训练
- **核心需求**：针对特定场景的实战演练
- **典型场景**：加薪谈判、投诉维权、砍价
- **使用动机**：迫切的现实需求，目标明确

### 3.4 情绪识别服务

情绪识别是驱动"树洞/建议/混合"三种模式的核心能力，通过多层分析引擎实现对用户情绪状态的精准判断。

#### 3.4.1 三层分析引擎

**第一层：文本情感分析**

| 分析维度 | 技术方案 | 说明 |
|---------|---------|------|
| 情感极性 | LLM内嵌情感分析能力 | 识别正面/负面/中性情感 |
| 情绪强度 | 基于关键词频率计算 | 0-100分，数值越高情绪越强 |
| 情绪类型 | 预设情绪词典匹配 | 支持6种核心情绪：快乐、平静、紧张、焦虑、沮丧、愤怒 |
| 语言风格 | 句式结构分析 | 识别感叹句、疑问句、否定句等 |

**第二层：行为分析**

| 分析维度 | 技术方案 | 说明 |
|---------|---------|------|
| 输入速度 | 计时分析 | 打字速度反映紧张程度 |
| 输入长度 | 字符计数 | 简短输入可能表示情绪低落 |
| 回复间隔 | 时间统计 | 长时间停顿可能表示思考或犹豫 |
| 选择模式 | 选项统计 | 频繁选择安全选项可能表示缺乏自信 |

**第三层：语音情绪分析（V1.1阶段）**

| 分析维度 | 技术方案 | 说明 |
|---------|---------|------|
| 语速 | 实时语音分析 | 过快/过慢可能表示情绪波动 |
| 语调 | 音高变化检测 | 语调起伏反映情绪强度 |
| 音量 | 分贝监测 | 异常音量可能表示激动或低落 |
| 停顿 | 间隔分析 | 频繁停顿可能表示紧张 |

#### 3.4.2 融合决策规则

```
用户输入
  │
  ├── 文本情感分析 ──→ 情感得分(0-100)
  │
  ├── 行为分析 ──────→ 行为特征向量
  │
  └── 语音分析(V1.1) → 语音特征向量
        │
        ▼
┌─────────────────────┐
│   融合决策引擎       │
│  加权融合计算        │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│   模式判定           │
│  树洞/建议/混合      │
└─────────────────────┘
```

**加权融合公式：**

```
综合情绪得分 = 文本情感权重(60%) × 情感得分 +
              行为分析权重(30%) × 行为特征值 +
              语音分析权重(10%) × 语音特征值(V1.1)
```

**模式判定规则：**

| 综合情绪得分 | 判定模式 | 说明 |
|-------------|---------|------|
| 0-30 | 树洞模式 | 用户情绪低落，需要情感支持 |
| 31-70 | 建议模式 | 用户情绪正常，需要实用建议 |
| 71-100 | 混合模式 | 用户情绪复杂，需要情感支持+实用建议 |

#### 3.4.3 成本优化方案

| 策略 | 说明 | 预估效果 |
|------|------|---------|
| 缓存高频情绪模式 | 相同输入模式的情绪判定结果缓存5分钟 | 减少30%重复计算 |
| 分级计算 | MVP阶段：普通用户仅文本分析，VIP用户启用文本+行为两层分析；V1.1阶段：VIP用户启用完整三层分析（含语音分析） | 降低50%计算成本 |
| 异步计算 | 行为分析和语音分析(V1.1)异步执行，先返回基础判定结果 | 响应时间<1秒 |
| 本地计算 | 文本情感分析基础规则在客户端计算，复杂分析在服务端 | 减少60%服务端请求 |

### 3.6 LLM混合引擎架构

```
用户输入
  │
  ▼
┌───────────────┐
│   LLM路由器    │
│ (LLM Router)  │
└───────┬───────┘
        │
        ├── 体验用户(1次) ──────→ DeepSeek API
        │
        ├── 免费用户 ──────────→ Ollama + 10%偶遇DeepSeek
        │
        ├── 日卡/周卡/月卡 ────→ DeepSeek API
        │
        ├── 年卡 ──────────────→ DeepSeek API (高优先级队列)
        │
        └── 健康检查失败 ──────→ 自动降级Ollama
```

**路由规则详解：**

| 用户类型 | LLM分配策略 | 说明 |
|---------|------------|------|
| 体验用户 | DeepSeek（仅1次） | 首次体验使用高质量模型，展示产品价值 |
| 免费用户 | Ollama为主，10%概率偶遇DeepSeek | 控制成本，偶尔回升质量让用户体验差异 |
| 日卡用户 | DeepSeek | 付费享有高质量对话 |
| 周卡用户 | DeepSeek | 付费享有高质量对话 |
| 月卡用户 | DeepSeek | 付费享有高质量对话 |
| 年卡用户 | DeepSeek（高优先级） | 最高优先级队列，响应更快 |

**健康检查与降级机制：**

- 每30秒对DeepSeek API进行健康检查（发送test prompt）
- 连续3次检查失败 → 自动降级到Ollama
- 降级后每60秒尝试恢复DeepSeek
- 恢复成功后逐步切回DeepSeek（先切免费用户，再切付费用户）
- 降级事件写入日志，触发告警通知

### 3.7 成本控制策略

| 策略 | 说明 | 预估效果 |
|------|------|---------|
| LLM混合路由 | 免费/低级用户走本地Ollama，付费用户走DeepSeek | 减少API调用约80% |
| 内容预编译 | 常见场景的开场白、过渡语、通用反馈预生成缓存 | 60%走预设内容 |
| 本地优先训练积分 | 训练积分计算在客户端完成，服务端仅校验 | 减少服务端计算压力 |
| 对话上下文压缩 | 超过10轮对话后，压缩历史上下文再发送LLM | 减少token消耗 |
| 缓存热门场景 | 热门场景的教练回复模板缓存在Redis | 减少重复LLM调用 |

### 5.3 预设教练角色

#### 教练1：沈清欢（鼓励型）

- **教学风格**：鼓励型——以正向反馈为主，善于发现用户的闪光点
- **性格描述**：温柔知性的大姐姐，总是能看到你做得好的地方
- **适合用户**：社交焦虑人群、需要建立信心的初学者
- **系统提示词关键词**：positive-reinforcement, empathy-first, gentle-guidance

#### 教练2：陆北辰（支持型）

- **教学风格**：支持型——提供具体可操作的建议，陪伴式引导
- **性格描述**：稳重可靠的朋友，给你最实用的建议和坚定的支持
- **适合用户**：职场新人、需要方法论指导的用户
- **系统提示词关键词**：practical-advice, step-by-step, reliable-support

#### 教练3：顾星河（挑战型）

- **教学风格**：挑战型——适度施压，推动用户走出舒适区
- **性格描述**：犀利但真诚的挑战者，相信你能做得更好
- **适合用户**：沟通能力提升者、已经有一定基础想突破的用户
- **系统提示词关键词**：constructive-challenge, push-boundaries, honest-feedback

#### 教练4：苏念（分析型）

- **教学风格**：分析型——用数据和逻辑拆解社交情境，理性分析
- **性格描述**：冷静理性的分析师，帮你看到社交背后的规律
- **适合用户**：高难度场景需求者、喜欢理解底层逻辑的用户
- **系统提示词关键词**：analytical-deconstruction, pattern-recognition, logic-driven

### 5.4 教练性格维度

每个教练（含自定义教练）具有四个性格维度，每个维度为二选一：

| 维度 | 选项A | 选项B | 说明 |
|------|-------|-------|------|
| 社交能量 | 外向(E) | 内向(I) | 影响教练的主动性和话题发起频率 |
| 信息处理 | 实感(S) | 直觉(N) | 影响教练关注细节还是全局 |
| 决策依据 | 感性(F) | 理性(T) | 影响教练反馈中情感和逻辑的比重 |
| 生活态度 | 计划(J) | 随性(P) | 影响教练训练节奏的结构化程度 |

**预设教练性格配置：**

| 教练 | 社交能量 | 信息处理 | 决策依据 | 生活态度 |
|------|---------|---------|---------|---------|
| 沈清欢 | E(外向) | N(直觉) | F(感性) | P(随性) |
| 陆北辰 | I(内向) | S(实感) | F(感性) | J(计划) |
| 顾星河 | E(外向) | N(直觉) | T(理性) | P(随性) |
| 苏念 | I(内向) | S(实感) | T(理性) | J(计划) |

### 5.5 教练即时状态系统

#### 情绪系统

教练具有三个情绪维度，数值范围0-100：

| 维度 | 低(0-30) | 中(30-70) | 高(70-100) |
|------|----------|-----------|------------|
| 愉悦 | 沉闷、严肃 | 平和、自然 | 开心、兴奋 |
| 焦虑 | 放松、从容 | 正常关注 | 紧张、担忧(为用户) |
| 疲惫 | 精力充沛 | 正常 | 疲倦(训练过久) |

**情绪变化规则：**

- 用户完成训练 → 愉悦+10
- 用户获得高分 → 愉悦+15，焦虑-10
- 用户连续训练超30分钟 → 疲惫+10
- 用户长时间未训练(>3天) → 焦虑+15
- 每日重置：愉悦→70，焦虑→30，疲惫→20

#### 记忆系统

- 存储：MySQL JSON字段 `memory_fragments`
- 内容：用户偏好、关键对话摘要、训练里程碑
- 更新时机：每次训练结束后，LLM提取关键信息更新
- 容量限制：最多保留最近50条记忆片段
- 淘汰策略：FIFO，超过50条时淘汰最早的记忆

### 5.6 教练切换规则（v2.3新增）

| 规则项 | 说明 |
|--------|------|
| 切换频率 | 免费用户每月限切换1次，会员不限 |
| 切换方式 | Tab5"我的页"→"教练设置"→"切换教练" |
| 好感度继承 | 每个教练独立好感度，切换后显示该教练的好感度 |
| 重置成本 | 免费用户切换后新教练从Lv.0开始，会员可保留原教练好感度80% |
| 切换确认 | 弹窗确认："切换教练后，你将与当前教练的师徒关系暂时中断，确定切换吗？" |

**切换流程：**

```

```

### 5.6 人格一致性保障

**双重校验机制：**

1. **前置——系统提示词**：每次LLM调用注入教练人格描述+当前情绪状态+最近5条记忆
2. **后置——输出校验**：LLM回复经过校验层，检测是否偏离人格设定

**校验规则：**

- 鼓励型教练不应出现纯粹批评（必须有建设性建议）
- 挑战型教练不应过度安慰（必须有推动）
- 分析型教练不应纯情感输出（必须有逻辑分析）
- 偏离校验失败 → 重新生成（最多3次，3次失败则使用兜底回复）

**三种思考方向的定义（v2.3新增）：**

| 方向 | 说明 | 适用场景 |
|------|------|---------|
| **A方向（主动型）** | 具体描述，展现热情和自信 | 相亲、面试、表白等需要展现自我的场景 |

### 6.4 阶段解锁规则

阶段是学习路径和页面分组，不是自动解锁开关。首登免费选择一个官方场景；此后的每个锁定场景单独校验“等级进度积分达到最低等级 + 可用积分足够 + 时空穿梭券足够”，用户确认后一次性扣除可用积分和券并永久解锁。会员只在会员有效期内获得全部场景访问权，到期后恢复到本人已永久解锁的范围。

| 校验项 | 口径 |
|------|---------|
| 等级 | 取累计获得的等级进度积分，消费可用积分不会降级 |
| 积分 | 取当前可用余额，用于支付解锁成本；不得用余额推断等级 |
| 时空穿梭券 | 按账号余额扣除，受持有上限约束 |
| 阶段完成记录 | 用于推荐和进度展示，不自动改变其他场景的 `unlocked` 状态 |

**解锁校验逻辑：**

1. 查询用户训练积分
2. 查询用户在各阶段的完成记录
3. 同时满足等级、可用积分和券条件后，展示二次确认
4. 服务端事务扣除资源并写入唯一解锁记录；Web 原型使用本地存储演示
5. 解锁后刷新场景列表，解锁事件记入成就系统

#### 6.5.4 评分规则（v2.3新增）

**三维评分体系：**

| 分析维度 | 说明 | 权重 |
|----------|------|------|
| 内容完整性 | 是否回答了问题？信息是否具体？ | 40% |
| 表达得体度 | 语言是否清晰？语气是否得体？ | 30% |
| 思路匹配度 | 是否参考了提示的思路？执行如何？ | 30% |

**评分计算方式：**

```
综合得分 = 内容得分 × 0.4 + 表达得分 × 0.3 + 思路得分 × 0.3
```

**各维度评分标准：**

| 维度 | 0-3分 | 4-6分 | 7-10分 |
|------|-------|-------|--------|
| **内容完整性** | 未回答问题或回答完全无关 | 回答了问题但不够具体 | 回答了问题且信息具体丰富 |
| **表达得体度** | 语言混乱、语气不当 | 语言基本清晰、语气尚可 | 语言清晰流畅、语气得体自然 |
| **思路匹配度** | 完全未参考任何思路 | 部分参考了某个思路 | 很好地运用了某个思路 |

#### 6.5.5 反馈内容结构（v2.3新增）

每条回答后的反馈包含五个部分：

```

你回答了对方关于工作的问题，并且主动反问对方，展现了对话意愿。

【为什么可以更好】
你的回答比较简短，没有具体说明工作内容。对方可能想了解更多。

【应该怎么说】
```

### 6.6 完整场景列表与解锁条件（v2.4校正版）

**核心逻辑：**

首登免费用户从官方目录确认 1 个场景；确认后其余场景不再自动开放。后续每个锁定场景都要同时满足三个条件：

|------|------|

- 训练开始即占用当日一次额度，主动退出不返还，防止反复开始/退出刷次数。
- 完成度低于70%或净得分低于30分时，本次不发放训练积分和好感度，但保留反馈、训练记录和能力建议；不扣除已有积分、不降低等级、不对用户贴负面标签。
- 可消费积分与等级进度积分分离：消费只减少余额，等级进度只增不减；免费用户等级进度累计获得积分上限为2000，会员有效期内不受该上限影响。
- 同一场景每日第4次起训练积分减半；双倍积分卡只能在满足正常结算条件时消耗，结算失败不扣卡。

### 8.7 积分经济模型（v2.3新增）

- 通关净收益为负值或接近零
- 平均每关获得积分：20-50分
- 解锁下一个场景消耗：100-300分 + 穿梭券
- 用户需要训练3-6个已解锁场景才能攒够资源解锁1个新场景

## 9. 好感度系统（v2.3新增）

### 9.1 好感度核心定位

**好感度不是"分数"，而是"师徒默契度"——反映教练对用户学习状态的了解程度和投入意愿。**

| 维度 | 说明 |
|------|------|
| **本质** | 教练对用户的"教学投入度"，而非用户的表现分数 |
| **增长方式** | 用户表现出"学习意愿"（认真对待训练、主动改进、持续练习）时增长 |
| **作用** | 解锁更高质量的教学反馈，而非解锁功能本身 |
| **不消耗** | 好感度本身不作为支付余额；仅用于教学权益和场景解锁积分折扣，负向变化只按明确规则发生 |

### 9.2 好感度获取规则

| 行为 | 好感度变化 | 说明 |
|------|:---:|------|
| 完成1次场景训练 | +2 | 基础奖励 |
| 训练评分≥80分 | +3 | 表现优秀 |
| 训练评分≥90分 | +5 | 表现卓越 |
| 完成真实挑战 | +3 | 学以致用 |
| 连续7天训练 | +10 | 持续学习 |
| 修改回答后改进（用券） | +3 | 主动学习和改进 |
| 完成真实模拟作业 | +3 | 认真完成作业 |
| 送对教练喜好礼物 | +5~8 | 详见送礼系统 |
| 送对未发现喜好礼物 | +8~12 | 详见送礼系统 |

### 9.3 好感度扣除规则

**核心原则：好感度只扣"态度问题"，不扣"能力问题"。**

> **v2.4.2 当前实现：** Web 原型已启用可见、有限、可追溯的负向规则；扣减只针对明确态度问题，不针对能力、低分或用户退出。每次扣减会即时提示并写入本地原因日志，服务端审核、申诉、跨设备同步和不可变流水仍属于生产待实现，不能把本地结果当成最终权益账本。

| 行为 | 好感度变化 | 说明 |
|------|:---:|------|
| 训练中途退出 | 0 | 尊重用户自主退出；未完成训练不发放本次奖励，也不额外惩罚 |
| 连续3次明确敷衍回答 | -3 | 同一训练最多触发一次；仅识别“嗯/哦/随便/都行/不知道”等明确敷衍短语，正常简短回答不自动扣 |
| 连续3个未登录日 | -1/日 | 从第3个未登录日开始按日衰减；单次登录补算最多7点，登录时明确提示 |
| 明确输入不当或攻击性内容 | -5 | 训练内拦截并提示；同一训练最多触发一次，格式问题（空/超长）不扣 |

### 9.4 好感度等级与教学增益

| 等级 | 名称 | 好感度区间 | 解锁特权 |
|------|------|:---:|---------|
| Lv.0 | 初识 | 0-19 | 基础教学（仅有思考方向提示） |
| Lv.1 | 熟悉 | 20-49 | **示范回答**：显示该方向的完整示例回答 |
| Lv.2 | 信任 | 50-79 | **完整分析**：为什么错、为什么对、应该怎么说 |
| Lv.3 | 默契 | 80-119 | **个性化教学**：针对用户常见错误定制建议 |
| Lv.4 | 师徒 | 120-179 | **复习挑战**：教练主动发起"复习挑战" |
| Lv.5 | 知己 | 180+ | **专属教练**：完全个性化的教学风格 |

### 9.8 训练弹窗提示系统（v2.3新增）

> 核心原则：在用户还没有体验过核心价值之前，所有的规则都是噪音；在用户体验过核心价值之后，所有的规则都是线索。用户应该先"感受到有用"，再"了解怎么用"。

#### 9.8.1 提示时机综合评估

| 时机 | 用户此时的状态 | 是否适合弹窗 | 最佳方式 |
|---|---|---|---|
| 首次体验结束（训练报告页） | 刚完成训练，感受到成就感，心情开放 | ✅ 是 | 嵌入报告页底部（不弹窗） |
| 首次体验中点击X退出 | 想离开，不耐烦 | ❌ 否 | **不提示好感度**，只提示"退出将丢失进度" |
| 非首次体验点击X退出 | 训练中想离开 | ⚠️ 谨慎 | **轻提示**，半屏弹窗+"下次继续" |
| 每次开始训练前（首次除外） | 有期待感，愿意接收信息 | ✅ 是 | **顶部轻提示横幅**，3秒后自动消失，不阻塞操作 |

**核心原则：**

- **正向时刻**（训练完成、开始训练）→ 可以提示，用嵌入或弹窗
- **负向时刻**（用户想退出）→ **不提示好感度**，只提示进度丢失，避免增加用户烦躁感

#### 9.8.2 提示触发条件

| 场景 | 是否提示 | 说明 |
|---|---|---|
| 第一次登录，第一次点击"开始训练" | ❌ 不显示好感度横幅 | 首次链路已有欢迎、选择确认和解锁成功提示，不再增加认知负荷 |
| 第一次训练中点击X退出，重新点击"开始训练" | ✅ 顶部横幅 | 标记 `hasStartedTrainingBefore = true`，显示好感度权益提示 |
| 第一次训练结束，重新点击"开始训练" | ✅ 顶部横幅 | `hasCompletedFirstTraining = true` 后触发 |
| 第二次登录，点击"开始训练" | ✅ 顶部横幅 | 已保存 `hasStartedTrainingBefore`，触发提示；不是阻塞弹窗 |

#### 9.8.4 各时机具体设计

**时机一：首次体验训练结束（训练报告页）**

- 触发条件：用户完成首次训练后，进入训练报告页时
- 展示方式：嵌入训练报告页底部（非弹窗），用卡片形式展示当前好感度等级+权益
- 仅在"首次体验"时显示，不干扰用户查看训练结果

**时机二：首次体验中点击X退出**

- 触发条件：用户在首次体验训练过程中，点击"X"返回按钮
- 弹窗类型：半屏弹窗（不提示好感度）
- 内容：只提示"退出将丢失进度"，不提示好感度，避免增加用户烦躁感

**时机三：非首次体验点击X退出**

- 触发条件：用户在非首次体验训练过程中，点击"X"返回按钮
- 弹窗类型：半屏弹窗（轻提示）
- 内容：提示"当前训练已完成 X/Y 轮"，"未完成进度和本次奖励不保存"，"下次可重新开始"
- 不保存中途分数，不暗中扣除好感度；如果未来支持断点续训，应同步修改文案和数据规则

**时机四：每次开始训练前**

- 触发条件：用户点击"开始训练"后，且 `hasStartedTrainingBefore = true`
- 展示方式：顶部横幅展示当前好感度等级、最近解锁权益、下一级预告，3秒自动消失
- 首次训练不显示；用户可手动关闭，关闭不影响训练

#### 9.8.5 交互流程图

```
用户进入训练准备页
  │
  ▼
判断 hasStartedTrainingBefore
  │
  ├─ false（首次）→ 不弹窗，直接进入训练
  │                   │
  │                   ▼
  │              userData.hasStartedTrainingBefore = true
  │
  └─ true（非首次）→ 显示好感度等级+权益横幅（不阻塞）
                       │
                       ▼
                   3秒自动消失或用户手动关闭
  │
  ├─ 首次体验 → 训练完成 → 训练报告页底部显示好感度等级+权益卡片
  ├─ 首次体验 → 点击X退出 → 弹窗"退出将丢失进度"（不提示好感度）
  ├─ 非首次体验 → 训练完成 → 训练报告页不显示好感度卡片（避免重复）
  └─ 非首次体验 → 点击X退出 → 弹窗"确认退出"（轻提示）
```

#### 9.8.6 前端实现要点

- 新增 `hasStartedTrainingBefore` 字段到 `userData`，用于追踪用户是否曾经开始过训练
- 新增 `getFavorabilityConfig(level)` 函数，返回对应好感度等级的配置（名称、图标、颜色、权益列表、下一级预告）
- `startTraining()` 函数中检查 `hasStartedTrainingBefore`，为 true 时调用 `showTrainingReminderModal()`
- `showTrainingReminderModal()` 保留历史函数名，但实际生成非阻塞顶部横幅
- 弹窗内容根据 `getFavorabilityLevel(userData.favorability)` 动态计算

### 12.2 训练对话框样式

两种训练对话框样式保持一致，仅通过以下标识区分：

| 界面元素 | 普通训练 | 真实模拟训练 |

### 12.3 三种触发真实模拟的场景

**场景一：用户表现优秀（无需强制）**

- 触发条件：所有技能点得分≥70分
- 处理方式：✅ 不强制，但推荐"试试无提示挑战吗？"

**场景二：用户存在薄弱点（必须布置作业）**

- 触发条件：有技能点得分＜60分
- 处理方式：📋 教练自动布置薄弱点作业 → 必须完成真实模拟训练

**场景三：用户依赖提示（强制检验）**

- 触发条件：技能点得分在60-69分之间（及格但不扎实）
- 处理方式：🔄 强制进入"无提示检验模式" → 验证是否真的学会了

### 12.4 真实掌握检验的完整流程

```
用户完成普通训练
    │
    ▼
系统识别有技能点在60-69分区间
    │
    ▼
弹出提示："你已经初步掌握了这个场景的部分技能！为了检验真实掌握程度，请进入真实模拟模式再次练习。"
    │
    ▼
用户进入真实模拟训练（无提示、无得分）
    │
    ▼
真实模拟得分≥70分 → ✅ 验证通过，标记"已掌握"
真实模拟得分≤59分 → ❌ 检验失败，布置专项强化作业
真实模拟得分60-69分 → ⚠️ 勉强通过，建议巩固一次
```

## 12. 语音训练系统

### 12.1 技术架构

```
用户语音输入
  │
  ▼
声网Agora RTC (采集+传输, <500ms)
  │
  ▼
语音识别 (ASR)
  │
  ▼
文本
  │
  ▼
LLM分析 (对话内容+语速+音量+停顿)
  │
  ▼
TTS合成 (Azure TTS, 教练音色)
  │
  ▼
教练语音回复 (Agora RTC播放)
```

### 12.2 语音训练模式

**流程：**

1. 教练提出问题（语音+文字同步）
2. 用户语音回答（最长60秒/轮）
3. 系统实时语音识别转文本
4. LLM分析回答内容 + 语速 + 音量 + 停顿
5. 教练给出语音反馈（内容评价+表达建议）
6. 进入下一轮

**语音分析维度：**

| 维度 | 分析内容 | 评分影响 |
|------|---------|---------|
| 语速 | 过快(>5字/秒)/过慢(<2字/秒)/适中 | 表达力±5 |
| 音量 | 过大/过小/适中 | 沟通力±3 |
| 停顿 | 合理停顿(思考)/过多停顿(紧张) | 应变力±5 |
| 流畅度 | 结巴次数/重复次数 | 表达力±5 |

### 12.3 语音训练权限

- 累计等级进度积分≥400（铂金学员）后可申请解锁
- 周卡/月卡/年卡会员在有效期内直接访问
- 免费/日卡用户需达到铂金等级
- 正式接入后每次开始占用1次当日训练额度；不得通过语音入口绕过免费额度

**教练挂断机制说明：**
训练积分≤15属于极端情况下的兜底设计，在实际用户场景中极少发生。触发后教练不会直接挂断，而是先进行温和提醒（如"我注意到你似乎有些困扰，要不要换个方式试试？"），如果用户持续使用不当语言或连续冷场，才会触发挂断。

### 12.4 语音训练分阶段实施

| 阶段 | 能力 | 说明 |
|------|------|------|
| MVP | AI教练语音播放(TTS) + 用户文字回复 | 教练用语音"说话"，用户仍用文字回复，降低技术复杂度 |
| V1.1 | 完整语音训练(用户语音输入+ASR识别+教练语音回复) + 口型同步 | 集成Agora RTC+ASR，实现全双工语音对话；3种口型（开/合/抿）与TTS音频精确同步 |

### 13.1 时空穿梭（v2.3完整设计）

**功能描述：** 用户可以使用"时空穿梭券"回到关键分支点重新选择，或解锁新场景，或解锁完整分析。

**时空穿梭券三大用途：**

| 用途 | 消耗数量 | 说明 |
|------|:---:|------|
| 错误补救（原功能） | 1张 | 回到训练中的关键分支点重新选择，每次训练限2次 |
| 解锁新训练场景 | 1-3张 | 与等级积分配合使用，详见场景解锁表 |
| 解锁单次完整分析 | 1张 | 免费用户用券解锁被隐藏的完整教练分析 |

**用途一：错误补救**

**使用流程：**

1. 训练中，每轮选择后显示"穿梭"按钮
2. 点击"穿梭"→消耗1张时空穿梭券
3. 画面出现时空倒流动效
4. 回到该轮选择前，重新展示思考方向提示
5. 用户重新输入回答，教练基于新回答继续对话
6. 原回答和新回答的对比展示（可选）

**限制规则：**

- 每次训练最多使用2张
- 只能回退到当前轮次，不能跨轮回退
- 使用穿梭券不影响训练评分（鼓励试错学习）
- 穿梭后教练会特别点评两个回答的差异

**用途二：解锁新训练场景（v2.3新增）**

**使用流程：**

1. 用户在场景列表页看到未解锁的场景卡片
2. 场景卡片显示解锁所需条件（等级+积分+穿梭券）
3. 用户点击"解锁"按钮 → 弹出确认弹窗
4. 系统校验条件是否满足：
   - ✅ 等级达标 → 显示绿色对勾
   - ✅ 积分足够 → 显示绿色对勾，扣除积分
   - ✅ 穿梭券足够 → 显示绿色对勾，扣除穿梭券
5. 条件全部满足 → 解锁成功，场景变为可训练状态
6. 条件不满足 → 显示红色提示，不可解锁

| 自定义场景创建 | 按会员方案额度 | 不适用 | 不适用 | 不适用 |

## 16. 心理健康教育模块

### 16.1 CBT（认知行为疗法）

**核心理念：** 帮助用户识别和改变不合理的自动化思维。

**CBT触发条件：** 当用户表达包含"我不行""我做不到""我永远也...""我一定说不好""他们肯定觉得我很蠢"等负面自动化思维时，AI教练会引导用户使用CBT思维记录表，帮助用户：
1. 识别自动化思维
2. 评估思维的真实性
3. 生成替代性思维
4. 在后续对话中验证新思维

**训练内容：**

| 练习 | 描述 | 触发场景 |
|------|------|---------|
| 识别自动化思维 | 在对话中识别"我一定说不好""他们肯定觉得我很蠢"等消极思维 | 社交焦虑相关场景 |
| 认知重构 | 将"我一定说不好"重构为"我可以试试，说不好也没关系" | 评估报告中推荐 |
| 行为实验 | 在安全环境中验证认知是否真实 | 场景训练中的A/B/C选项 |

### 16.2 NVC（非暴力沟通）

**四步法：**

1. **观察**：客观描述事实，不加评判（"当你打断我说话时..."）
2. **感受**：表达自己的感受（"我感到有些沮丧..."）
3. **需要**：说出自己的需要（"因为我需要被尊重..."）
4. **请求**：提出具体的请求（"你愿意让我把话说完吗？"）

**NVC触发条件：** 在冲突类场景（如"被误解(NVC)""投诉物业""4S店砍价"等）中，如果用户选错选项导致对话走向恶化，AI教练会弹出NVC四步法引导，帮助用户重新组织表达。

**训练场景：**
- 被误解(NVC)场景：专门练习NVC四步法
- 冲突处理场景：在冲突中应用NVC
- 投诉场景：用NVC方式表达不满

### 16.3 情绪识别训练

| 训练内容 | 描述 | 形式 |
|---------|------|------|
| 识别自己的情绪 | 在训练中标注自己的情绪状态 | 每轮对话后选择当前情绪 |
| 识别他人情绪 | 判断对话中对方的情绪变化 | 场景中对方表情/语气线索 |
| 情绪命名 | 准确描述情绪词汇 | 情绪词汇匹配练习 |

### 16.4 三级心理响应机制

| 级别 | 触发条件 | 响应方式 |
|------|---------|---------|
| 轻度 | 用户表达轻微负面情绪（如"有点紧张"） | AI教练安慰+鼓励，推荐相关训练场景 |
| 中度 | 用户表达持续负面情绪或认知偏差 | 推荐CBT练习，引导认知重构 |
| 重度 | 用户表达自伤/绝望等危险信号 | 立即显示心理援助热线+建议寻求专业帮助 |

**重度响应流程：**

1. LLM输出中检测到危险关键词
2. 立即中断当前训练
3. 弹出心理援助热线信息（24小时热线）
4. 建议用户寻求专业心理咨询
5. 记录事件日志（脱敏处理）
6. 24小时内不推荐高强度训练

### 18.6 收入闭环与成本门槛

上线前的经营指标与成本保护：

- 记录曝光、试用、支付发起、支付成功、退款、续费和流失漏斗；不要用虚假的本地“购买成功”提升转化数据。

- 设置异常调用限频、设备/账号风控、未成年人消费限制、退款观察期和人工申诉入口；不通过负向惩罚逼迫付费。
- 当前代码和演示页面处于“支付未配置”状态，不能产生真实收入；接入微信/支付宝前需完成商户资质、密钥保管、回调验签、退款和对账验收。

## 21. API接口设计

### 21.1 通用规范

| 项目 | 规格 |
|------|------|
| 协议 | HTTPS |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601 (2026-07-15T08:30:00Z) |
| 认证方式 | Bearer Token (JWT) |
| 分页参数 | page(页码,默认1) + page_size(每页数量,默认20,最大50) |
| 错误响应 | `{"code": 40001, "message": "错误描述", "details": {}}` |

**通用状态码：**

| HTTP状态码 | 含义 |
|-----------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 429 | 请求过于频繁 |
| 500 | 服务器内部错误 |

### 21.2 认证模块

#### POST /api/auth/register

**描述：** 用户注册，触发实名认证流程

**请求体：**

```json
{
  "phone": "13800138000",
  "code": "123456",
  "nickname": "小明"
}
```

**响应体：**

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "user_id": 10001,
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "real_name_required": true,
    "real_name_level": 0
  }
}
```

**业务规则：**
- 手机号必须唯一
- 验证码6位，5分钟有效
- 注册后默认创建growth_profiles记录(五维50分)
- 注册后默认分配鼓励型教练(沈清欢)
- 注册后标记real_name_required=true，引导完成实名认证

### 13.2.2 原始课程知识库（2026-09-10）

学习卡片入口位于训练功能区。除结构化场景话术外，系统纳入原始《好好接话》课程：正文按 9 个章节组织，每个正文小技能标题作为一课，共 78 课。课程显示标题去除原始数字序号，正文内容逐字保留；原始目录、前言、章节导语、章节速记和全文转写均保留在 `knowledge_base/markdown/`。

当前 Web 原型将 49 个场景的 928 条结构化话术与 96 张原始课程卡片（78 课 + 18 张章节导语/速记辅助卡）合并，提供搜索、分类筛选、分页加载、收藏和复习，共 1024 个知识点。原始课程卡片附“参考材料/尊重边界”提示，不把原始文本自动判定为唯一正确答案。

G 盘中的 PDF、DOC/DOCX、PPT/PPTX、WPS、XLS、音视频等资料尚未批量转写；纳入前必须保留来源定位、版权范围、敏感内容审核和版本信息。

### 13.2.3 学习卡片课程化重构（2026-09-10）

学习卡片区域从"零散知识库"重构为"系统化微课"。原"学习卡片库"以单卡平铺展示 1024 个知识点，存在三个核心问题：
- 卡片内容溢出屏幕，底部被底部 Tab 遮挡，用户无法查看完整"核心原则"；
- 只展示"了解底价"这一条，不能打开"4S 店砍价"整节课的目录与教学流程；
- "显示 12 / 1024 个知识点"无法说明这 1024 个知识点是什么。

重构后的定位是"知识图书馆 / 微课中心"，而不是搜索列表。本轮重构以 1024 个**结构化场景话术**（49 场景 × 928 条 + 1024 增量课程）为主，以《好好接话》原始课程 78 课为辅，保留 `knowledge_base/learning_cards.js` 与 `knowledge_base/raw_course_cards.js` 原数据。

**整体架构与交互原则**

- **整页可滚动**：课程库首页与详情页都是长内容区，整页允许上下滑动，底部 Tab 由页面 `padding-bottom` 兜底，不被遮挡。
- **阶梯式展开（Accordion List）**：课程按"分类（即章节）"为一级卡片，每张分类卡内列出该分类下的全部技能（即小课）。点击小课标题展开该课内容，可折叠。
- **两种入口并存**：
  - 新入口 "课程库"（`modal-knowledge-library`）：以章节树的形式展示全部课程，支持搜索、按分类筛选、进度勾选。
  - 旧入口 "卡片库"（`modal-cards`，`showCards()`）：保留为复习型入口，单卡平铺 + 收藏 + 复习，兼容已有收藏夹数据。
- **关键词全文搜索**：搜索框支持"标题 / 副标题 / 场景 / 标签 / 关键句"全文匹配，命中后在课程库首页按"分类 → 命中课"两层折叠高亮。

**课程库首页（章节列表）**

- **顶部固定区**：
  - 标题"📚 课程库" + 右上角搜索图标（点击展开搜索框）。
  - 横向滑动的胶囊筛选标签：全部 / 日常生活消费 / 家庭与亲友 / 突发与冲突 / 公共服务与办事 / 社交场合与人际交往 / 亲密关系与约会 / 数字社交 / 职场与事业 / 好好接话课程。胶囊与训练中心配色对齐。
- **统计条**：已收录课程数 / 已学课程数 / 已收藏课程数；不允许出现"12 / 1024 知识点"这种冷冰冰的数字。
- **章节卡片**（Accordion 项）：
  - 顶部：分类图标 + 分类名 + 已学 / 总数 + 进度条。
  - 内部展开后：列出该分类下所有课，每行 = 序号 + 标题 + 标签（如"面试技巧 / 结构型 / ⭐推荐"）+ 状态打勾（已学 ✓ / 已收藏 ★ / 未学 —）。
  - 默认折叠第一章节，展开一项时其他自动折叠。
  - 章节标题点击 → 进入"章节概览页"（仅显示该章节下全部课程的紧凑列表）。
  - 单课标题点击 → 进入"课程详情页"。

**课程详情页（单课内容）**

详情页采用"微课"模板，分为五个模块，全部从 `learningCard` 字段映射，原始课程卡片自动按章节与序号补全：

1. **课程头部**：返回按钮 / 大标题（卡 title）/ 副标题（卡 scene 或所属章节）/ 标签（class 标签 + "推荐时长" + "已学 / 未学"勾标）。
2. **情境导入（案例区）**：
   - 红色框：错误示范或常见踩坑（取自 `principle` 或 `tags` 反义字段；无数据时用"易踩坑示范"占位）。
   - 绿色框：正确示范（取自 `content` 第一句）。
   - 用户在两个框之间看到对比，形成"反差学习"。
3. **核心原则（核心教学）**：高亮色块卡片，把 `principle` 用加粗字体、大字号呈现；下面列出 3-5 条"话术公式"（从 `tips` + `content` 拆分），等宽字体 / 代码块包裹，便于记忆。
4. **红线 / 避坑**：红色或橙色卡片，固定显示 `safetyNote`。
5. **练习与自测**：
   - 一道选择题（基于本课 `practicePrompt` 自动生成 A / B / C 三个选项：A 直接重复 `content`；B 是把 `content` 改写得更平；C 是明显错误的"暴露底牌"或"攻击性"版本）。
   - 一个自由输入框："用你自己的话完成一次表达"。
   - 提交后显示"AI 教练"即时点评：参考 6.5 节思路提示卡格式，区分"得体 / 一般 / 欠妥"三档。
6. **底部操作栏（固定悬浮）**：
   - "✅ 我已学会，去对练" 按钮：根据本课 `category` 自动跳到对应场景（`kb_int_*` → 面试训练；`kb_fj_*` → 饭局训练；`kb_yh_*` → 银行训练；`kb_jd_*` → 酒店训练；其他 → 自定义场景创建提示）。按钮在用户答对自测题后才点亮，否则置灰提示"请先完成自测"。
   - "📌 收藏" 按钮：写入 `collectedCards` 并打勾。
   - "🔁 复习" 按钮：复用现有 `startCardReview()`。

**全局规则**

- **不删减原则**：所有 1024 个知识点仍可被搜索、点击进入课程详情；详细正文（无论结构化还是《好好接话》原始正文）必须能在详情页或详情链接后的折叠区完整查看，不以摘要替代。
- **进度与打勾**：用 `userData.cardReviewProgress` 复用现有复习进度字段，`collectedCards` 复用现有收藏字段；新增 `userData.knowledgeProgress[id] = { opened: bool, practiced: bool, passedAt: timestamp }`，仅本地保存。
- **可访问性**：每个章节与课程项支持键盘 Enter / Space 展开或跳转；高对比模式沿用 `prefers-reduced-motion` 减少动效。
- **数据契约不变**：`learningCards` 数据源、`renderCardItem` / `renderCards` / `collectCard` / `removeCard` / `startCardReview` 等既有函数保持兼容；新模块读取同一数组，不新增并行知识库。
- **空状态**：搜索无结果时显示"换个关键词试试"和"显示全部"按钮，不出现"未知错误 / 加载失败"。

**改造清单**

- 新增模态 `modal-knowledge-library`、`modal-knowledge-detail`，CSS 与 JS 各自独立封装。
- 新增函数：`openKnowledgeLibrary()`、`getKnowledgeChapters()`、`renderKnowledgeChapter(id)`、`openKnowledgeDetail(id)`、`renderKnowledgeDetail(card)`、`startKnowledgePractice(id, choice)`、`jumpKnowledgeToPractice(id)`。
- 改造入口：训练中心 "学习卡片" 卡（`onclick="showTrainingModule('cards')"`）改为 `onclick="openKnowledgeLibrary()"`；首页学习卡片卡同样跳转。
- 兼容入口：保留旧"学习卡片库"模态（`showCards()`）作为复习入口，由课程详情页"复习"按钮调用。
- 课程详情页底部"✅ 我已学会，去对练"按钮按 `category` 映射调用 `startEtiquetteLevel(9001)` 等真实挑战或礼仪训练入口；无对应关卡时引导用户创建自定义场景。
- 通过 15 项浏览器回归（场景入口、模板市场、收藏夹、复习、自定义场景、真实挑战、礼仪训练、个人中心、好感度、签到）；新增 4 项知识库专项：搜索、章节展开、详情打开、自测提交。

### 13.2.4 训练界面 UI/UX 重构（准备 → 训练 → 复盘）（2026-09-10）

训练模态（包括真实挑战与社交礼仪训练）的现有界面把"场景图、对话气泡、A/B/C 选项、输入框、教练评价"全部堆在一个视口里，存在三个核心问题：用户不知道眼睛该先看哪里；策略选项只是文本列表，与游戏化场景不匹配；动作指令（鞠躬/点头/握手等）以一行文字平铺在底部，容易误触且占地方。本节定义"准备 → 训练 → 复盘"三阶段架构、统一视觉规范与交互规则，覆盖 §6.5（思路提示型界面）和 §12（真实模拟训练）的视觉一致性。

**一、三阶段架构（强制流程）**

1. **准备阶段（Pre-training）**：从场景市场、首页推荐、最近训练或初次免费选择进入训练时，必须先进入"训练准备"页（§23.5），不允许直接进入对话。准备页用深色磨砂玻璃背景，把"场景目标 / 形象准备 / 教学提示"分三块：
   - 顶部场景目标卡：图标化排版（👤 角色 / 🎯 目标 / ⭐ 难度），去表格线、用极简标签。
   - 中部形象准备：60% 形象适配度改为环形进度条 / 雷达图，更具游戏感。
   - 底部两个大按钮：【去悦己颜值社（模拟穿搭）】、【保持当前形象开始】。主次分明。
   - 悬浮"教练提示小气泡"：提醒用户"本次训练重点：第一印象 & 破冰"。

2. **训练阶段（In-training）**：采用"上半屏沉浸场景 + 下半屏交互教学"分屏：
   - **上半屏**：固定显示照片级双人场景（§23.6 已用 SD/真实素材合成）；NPC 头顶悬浮角色标签（角色名 · 身份 · 性格）；NPC 当前说话以气泡形式贴在头部。当前回合、剩余时间、道具状态压成一行微小胶囊标签贴在场景图顶部边缘，不干扰阅读。
   - **下半屏**：分为 (A) 对话历史（聊天气泡，从下往上滚动）→ (B) 策略选项（参考 §三）→ (C) 输入与发送 → (D) 教练实时评价（参考 §四）。

3. **复盘阶段（Post-training）**：训练结束展示能力雷达图（§4.4）+ 时间线（每轮选择 / 关键句 / 教练评分）+ 推荐下一步（继续 / 复习课程 / 关卡升级）。

**二、视觉规范**

- **主色调**：治愈蓝/紫（理智、专业）+ 暖橙/粉（社交、温度）。场景切换：咖啡馆用暖色调，相亲场景用柔和粉紫调，办公室用冷蓝灰，餐厅用橙色烟火气。
- **字体**：思源黑体 Bold（大标题）、思源黑体 Regular（正文）、Noto 手写体（教练点评）区分"机器/教练"与"主角/对手"的声音。
- **对话气泡（醒目样式）**：
  - NPC 气泡：白底 + 紫色描边 + 深色加粗正文，13.5px。
  - 用户气泡：紫渐变背景 + 白色粗字，13.5px。
  - 气泡贴头部锚点 y=H*0.40，最大宽 56%、最大高 96px，超出截断滚动。
- **场景道具**：办公 / 商务 / 餐厅场景给 NPC 加前景办公桌或餐桌（CSS `.photo-desk`），NPC 标 `.photo-char.seated` 缩放坐姿，头肩露出桌面。
- **动效**：点击动作时上半屏对应人物做局部微动效（鞠躬/点头/微笑等），使用 `.animating-*` 类做 1.35s 一次性动画；`prefers-reduced-motion` 下关闭。
- **可访问性**：高对比度模式沿用系统设置；移动端 360px 起保持两列分屏；触控目标不小于 44×44px。

**三、策略选项（Carousel + 即时点评）**

真实挑战 / 礼仪训练在"输入前"应展示策略选项（礼仪训练 A/B/C，真实挑战只展示动作指令可选）。本节定义统一规范：

- **水平滑动 Carousel**：A/B/C 改为横向滑动的卡片轮播（`overflow-x:auto; scroll-snap-type:x mandatory;`），每张卡 = 一种策略（主动 / 平衡 / 含蓄），宽 88%，snap 到中间。卡片正面 = 策略名 + 一句话示例；右上角 ⓘ 打开教练点评"为什么选这个策略更好"。
- **卡片交互**：点选 → 自动填入输入框（礼仪模式）或直接发送（真实挑战简版）；卡片收缩入对话框动效，避免选项堆叠。
- **真实挑战模式**：不强制 A/B/C，但保留"自由输入"框 + 动作指令按钮；输入前**无预提示**，符合"考试"定位。

**四、教练实时评价（浮层）**

- 触发时机：用户发送任意消息后立即出现，不修改对话气泡，仅在屏幕底部弹出半透明浮层（`.coach-feedback-overlay`）。
- 内容：评分 ⭐⭐⭐⭐ + 简短文字（"选择很稳妥，展现了礼貌" / "稍微有些激进，可以更柔和一些" / "✅ 动作得体 +2分" 等）。
- 自动消失：3.5 秒后淡出；不阻塞下一轮输入；用户可点击浮层右上角 ✕ 立即关闭。

### 13.2.5 训练界面固定分屏与角色动作示范（2026-09-10 追加）

§13.2.4 落地后发现两个体验缺陷：**（1）** 3D 场景与输入框处在同一个滚动容器内，用户一旦滚动去读「教学提示 / 教练分析」，照片级场景就被顶出视口，无法一边看示范一边学动作；**（2）** 提示内容与教练分析分散在输入框上下两侧，阅读动线来回跳。同时动作指令只让"用户角色"做动作，缺少"先看老师示范"的教学环节。本节定义训练界面的最终布局与动作示范规则。

1. **头部（固定）**：教练头像 / 场景名 / 角色定位，`flex-shrink:0`，不使用 `backdrop-filter`。

**二、角色动作示范（教学闭环）**

### 13.2.7 课程详情「逐节翻页」阅读模式（2026-09-10 追加）

反馈：**「目录里只有标题、没有具体知识；同一个技能下有多条内容时，应该一条条展示，看完一条点下一页看下一条」**。

**一、目录改造（不再"折叠展开"，改为"逐条可跳转"）**

原实现在目录中把「当前技能点」的全部参考表达一次性展开（`.kd-samples`），其余技能点只有标题，导致：目录占位很长、长场景（如「销售成交」310 条）无法定位、用户不知道每条讲什么。

新规则：

1. 同场景的**每一张卡片 = 一节**，按 `kind`（intro → lesson → summary）→ `round` → 原始顺序排序。
2. 目录项三要素：**序号** · **节标题** · **内容摘要**（取 `rawText || content || principle` 前 46 字）。摘要直接回应"目录没有具体知识"。
3. 目录项可点击，`data-id` + `KL_openDetailByAttr(this)` 跳转到对应节（沿用既有防引号逃逸约定）。
4. 同一 `title` 出现多条时，自动标注 **`（1/2）`/`（2/2）`**，明确"同一技能的多条表达，逐条学习"。
5. 节数 > 8 时目录容器 `.kd-outline.scrollable` 限高 `300px` 内部滚动，避免撑爆详情页。
6. 打开任意节后，目录自动滚动到当前节（`scrollOutlineToCurrent`），当前节高亮（左边框 + 紫底）。

**二、底部翻页栏（新增 `#knowledge-detail-pager`）**

详情模态结构升级为**四段**（自上而下）：头部 `/ .kd-scroll`（唯一滚动区）`/ #knowledge-detail-pager`（翻页，固定）`/ #knowledge-detail-actions-bar`（操作，固定）。

- 翻页栏内容：`← 上一节` · `当前节标题 + 第 N / M 节` · `下一节 →`。
- 首节 `上一节` 禁用，末节 `下一节` 禁用；同场景只有 1 节时整栏不渲染（高度为 0，不占位）。
- 翻页调用 `KL_goSceneStep(±1)`，切节后正文 `.kd-scroll` 回到顶部。
- 翻页栏与操作栏互不遮盖（`pager.bottom === bar.top`）。

**三、定位时序（易踩坑）**

`KL_openDetail` 的执行顺序是 `renderKnowledgeDetail → closeModal → showModal`，即**渲染时模态仍是 `display:none`**。此时子元素 `clientHeight` 为 0、`scrollTop` 赋值不生效。因此"目录定位 + 正文回顶"必须放进 `setTimeout(..., 0)`，在模态可见后执行。

### 23.4 用户真人全身头像预设（2026-09-10）

当前 Web 原型在“我的 → 编辑资料”提供 10 张不同社交气质的真人全身头像预设：沉稳沟通、温柔亲和、阳光运动、文艺知性、精英职场、创意街头、成熟导师、优雅从容、极简中性和自然随和（默认角色）。每张素材按完整比例展示，不裁切头脚；用户仍可上传自己的 JPG/PNG/WebP 全身照，最大 5MB，保存后仅进入当前设备账号数据。

头像预设用于训练中的用户头像和个人中心展示，属于形象表达选择，不对外貌、性别或社交能力作评价。生产上线前仍需完成真人感、文化适配、版权/安全、对象存储、鉴权、删除和跨设备同步审核。
### 23.5 训练前形象准备与评分（2026-09-10）

每次从场景市场、首页推荐、最近训练或初次免费选择进入训练，必须先进入“训练准备”页，再进入对话。准备页展示当前用户真人全身头像、场景适配度和三个明确动作：

- “选择 / 上传”：打开头像画廊，可选择真人全身预设或上传 JPG/PNG/WebP 全身照；头像画廊卡片主体用于选择，右下角放大按钮用于查看细节。
- “去悦己颜值社（模拟预览）搭配”：当前只展示场景化穿搭、妆容和发型建议；真实账号联动等待接入，不上传照片、不扣积分/券、不宣称已完成外部服务。
- “使用当前形象开始”：保留当前形象直接进入训练，但不会跳过准备页。

新账号首个预设为“沉稳沟通”真人全身形象；原默认入口改为自然随和真人角色并放在画廊末尾，仍可由用户主动选择。头像预设和本地上传照片仅保存在当前设备账号数据中，生产版需补齐对象存储、鉴权、删除、隐私授权和跨设备同步。

训练结算增加透明的形象准备维度：有真人头像但未进行场景搭配时记为基础 60 分，不产生额外加分；完成模拟搭配后按场景适配度 70–99 分计算，最多对本次净得分增加 8 分。该加分在报告中单独显示“形象准备分/评分贡献”，不会暗中扣分，也不改变单轮回答评价；对话内容、表达得体度和思路匹配度仍是主要评分依据。真实上线前须由产品、合规和用户研究共同确认权重，禁止对外貌、性别或身体特征进行评价。

### 23.6 训练中心布局（2026-09-10）

训练中心首页采用“一个主入口 + 六张专项卡”的控制台布局：场景模板市场作为全宽核心入口，真实挑战、学习卡片、我的作业、社交礼仪训练和语音训练以两列专项卡呈现。卡片保留原有入口函数、锁定与“即将上线”提示，仅调整信息层级、间距、色彩标记和状态徽章；语音训练仍明确标记等待更新，不伪装为已上线功能。该布局针对移动端 360px 以上宽度优化，小屏自动收紧间距并保留键盘焦点与减少动效支持。
