# 社交话术知识库使用说明

本目录把原始资料中的可复用沟通方法整理为训练素材。原始资料包含年代较早、行业特定、强调“套路/操控/逼单”的内容，不能把其中每一句话直接当成推荐答案。

## 质量原则

1. **真实优先**：示例中的经历、数据、报价、证人和承诺只能替换为用户真实且可核验的信息，不鼓励编造。
2. **边界与同意**：邀约、加联系方式、肢体接触、借钱和隐私问题都应允许对方拒绝；不把持续追问包装成“主动”。
3. **情境适配**：简短回答不天然低情商，正式办事、危机沟通和明确拒绝往往越简洁越好。
4. **先理解需求**：安慰或共情时先确认对方想被倾听、获得建议，还是需要实际帮助；不强行积极。
5. **具体而不武断**：描述可观察事实、自己的感受和明确请求，避免揣测对方动机、性格或身体感受。
6. **坚定而不威胁**：投诉和谈判可以说明规则、证据、期限与正规升级渠道，不使用羞辱、虚假筹码或舆论威胁。
7. **没有唯一标准答案**：训练示例是可改写的参考，不是必须逐字照搬的“正确话术”。评分应关注是否相关、真实、尊重、清楚和可执行。

## 占位符规范

统一使用方括号，如 `[姓名]`、`[真实项目]`、`[可核验数据]`。占位符必须在使用前替换；如果没有真实信息，应删去对应句子，不能为了完整而虚构。

## 场景脚本字段

- `purpose`：这一句在对话中的实际任务。
- `user_emotion`：适用情绪，不代表系统可以仅凭文字准确诊断情绪。
- `coach_style`：表达风格；风格不能凌驾于真实性和边界。
- `level`：表达方式标签，不代表人格高低。
- `text`：可改写示例。
- `tags`：检索标签。

## 维护检查

每次更新后应检查：所有 JSON 可解析；索引中的文件、条数和分类统计与实际一致；页面中的同名场景没有保留旧版不当话术；新示例不依赖性别刻板印象，也不因“话长、反问多、看起来积极”而自动获得高分。
